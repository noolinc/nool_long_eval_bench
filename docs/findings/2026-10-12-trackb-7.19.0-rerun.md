# Track B rerun against nool 7.19.0 (baseline 7.8.0)

**Status:** complete (B1–B9 regenerated, B10 smoke run) · 2026-10-12
**Context:** the committed Track B results were collected against nool 7.8.0
on 2026-09-16 (landing commit `1dd90c3`). Eleven minor releases later
(7.9.0 … 7.19.0, see the product's `docs/CHANGELOG.md`), the whole
deterministic track was re-run on the 7.19.0 release binary
(`aarch64-apple-darwin`, enterprise edition, sha256 `d161c3f1…`, build
`1fb8ed48`, clean tree) and landed over the 7.8.0 files as `fee5c83`. This
note is the cell-by-cell comparison of the two runs. Nothing here is a
Nool-vs-git finding; it answers one question — did any mechanism result move
between the two product versions — and records what did.

Both runs were on the same 12-core macOS machine with the machine quiet
(1-minute load per core 0.17–0.28 for 7.8.0, 0.22–0.37 for 7.19.0;
`provenance.system_load.quiet` is `true` on every result file of both runs).
The git control arms were re-run alongside, so environmental drift shows up
in both arms and can be separated from product change.

## Result in one line

Every correctness, precision, recall, false-positive, merge, guardrail and
retrieval cell is identical between 7.8.0 and 7.19.0. Timings moved 5–15%,
in the git arms as much as in the nool arms; two cells moved beyond that
and are open as Nool task `c0cf9bb3` (B1 hook latency, B2 op median at 15
writers). The comparison is recorded as Nool finding `f624e85a`.

The ratios that the README quotes come from the 7.19.0 row: fast-mode
landing is 6.5x (1 file), 9.8x (10 files) and 39x (100 files) a hooked git
commit; full mode is 10.1x, 14.0x and 54x the `go vet` hooked arm; bare git
is 11.5x / 17.2x / 71x behind in fast mode.

**Two cells beyond the drift.** Every git arm moved 4–16%, which bounds the
environmental component of the run. Two nool cells moved more:

1. **Hook latency** rose by a flat 3.2–3.6 ms on all five hooks (p90 moved
   the same amount). A constant added to every hook, including the ones that
   do nothing Nool-specific, points at per-invocation start-up (binary size,
   config or licence resolution, telemetry) rather than any hook's work.
2. **B2 at 15 writers**: the nool op median rose 33% (391 → 521 ms) while the
   N=2 and N=5 cells rose 12–15% and git's N=15 cell 4%. Wall time at N=15
   rose only 14%, so the extra cost is per operation under contention, not a
   serialisation of the whole run.

Both are filed as Nool task `c0cf9bb3` (profile with a debug build per the
product's `scripts/perf_sanity.sh` recipe); neither changes a correctness
cell and neither blocks a release under this suite's policy that benchmarks
are follow-up work, not release gates.

**B9 kotlin.** The per-language wall for kotlin went 3.0 s → 49.3 s while its
eight per-target measurements stayed at 16–19 ms with no errors. The extra
time therefore sits in that language's fixture setup and landing, not in the
blast-radius commands the benchmark scores. Single rep; noted, not filed.

## B10 smoke run and a fixture defect

`make b10-sanity` (R=100, D ∈ {0, 4}, one rep) was run on the frozen 7.19.0
binary. The first attempt reported a quietness warning against itself: load
19.8 on 12 cores. The cause was in the fixture, not the product — each
filler package's function called both of its imported predecessors, making
`H_i` a cross-package Fibonacci, so the untimed `go test ./...` warm-up could
not finish past about 45 fillers, timed out at 1,800 s, and left its
compiled test binaries spinning (bug `b0d15306`). The fix (`5b66a0bc`)
keeps both import edges but no longer calls through them; every filler test
is O(1), and the fixture's ground truth (closure files, envelope,
`affected_tests`) is unchanged. On the fixed fixture `go vet` and `go test`
pass all 100 packages in 39 s cold.

Rerun on the fixed fixture, quiet machine (0.28 load per core), against the
committed 7.9.2 reference (R=100, 3 reps):

| Metric | 7.9.2 reference | 7.19.0 rerun |
|---|---|---|
| go test warm-up | untimed | exit 0 in 30.3 s |
| D=0: selection / closure / admission | exact / ok / 216.3 ms | exact / ok / 105.7 ms |
| D=4: selection / closure / admission | exact / ok / 213.8 ms | exact / ok / 591.6 ms |
| D=0 / D=4 evidence | 1100 / 1107 ms | 1217 / 522 ms |
| landed / refused / dnf | 3/0/0 per cell | 1/0/0 per cell |
| concurrency | N=4: 4/4 landed, 333.6 ms | N=2: 2/2 landed, 166.8 ms |
| validate --all | 34.1 ms | 19.3 ms |
| leases left after `propose --abort` | 1 | 0 |
| unknown-path probe | 3 × unknown, 257.9 ms | landed, 17.3 s (full suite ran) |

Functionally clean: both cells landed with exact selection and an intact
closure, and the lease the 7.9.2 run left behind after `propose --abort` is
gone. The timings are single samples from a smoke run and are not entered
into `results/`; the D=4 admission figure in particular needs reps before it
means anything. The committed `results/micro/b10_assurance_scaling.json`
(nool 7.9.2) predates the fixture fix — see the pitfalls section of
`2026-09-16-b10-admission-cost.md` for which of its cells that touches.

```bash

# regenerate against an installed release binary (work/bin/nool, frozen by make b10-freeze)

PATH=$PWD/work/bin:$PATH make trackB          # B1–B9 into results/micro/
make b10-sanity                               # B10 smoke into work/b10_sanity/
python3 analysis/summarize.py                 # the tables above, both versions side by side
```

(`nool_build.git_sha` `1fb8ed48…`, `binary_sha256` `d161c3f1…`,
`system_load.quiet: true`). Both runs' B10 artefacts are under `work/` and
